# BT-1: box identity — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a `BoxId` — not a `NodeIdx` — the identity of geometry, hit order, scroll state and every layout cache, with the box tree built as an exact 1:1 mirror of the DOM so that behaviour is unchanged.

**Architecture:** A new `crates/rts-dom/src/caixas/` module owns a contiguous arena of boxes and the only `NodeIdx → Vec<BoxId>` map in the engine. In this lot every element produces exactly one box, so every entry has length one. Layout, the fragment cache and the geometry consumers are re-keyed onto `BoxId`. No anonymous boxes, no generated boxes, no behaviour change.

**Tech Stack:** Rust, `crates/rts-dom`. **No new dependencies.** A `Vec` is used rather than `SmallVec`: every entry has length one in this lot, and adding a dependency for an allocation that BT-3 may or may not make hot is a measurement that has not been taken.

**Spec:** `docs/ui/html-engine/box-tree.md` — read sections 3, 5, 6 and 7 before starting. Section 7 lists the nine invariants; this plan exists to make seven of them impossible rather than silent.

//! A ÁRVORE DE CAIXAS: o que o CSS diz que existe, entre o DOM e o layout.
//!
//! Existe porque o CSS gera caixas que nenhum elemento possui (as anónimas do
//! §9.2.1.1 e do §17.2.1) e elementos que possuem várias (um inline que
//! atravessa três linhas). Enquanto a identidade de uma caixa foi o `NodeIdx`,
//! nenhuma das duas era exprimível: `record_node_rect` guardava a última e
//! `union_rect` colapsava as outras na envolvente.
//!
//! **Este módulo é o ÚNICO sítio que traduz entre nó e caixa.** Se a tradução
//! aparecer noutro consumidor, o `NodeIdx` volta a ser a identidade por uma
//! porta lateral, que é exactamente o que o lote BT-1 existe para fechar.
//!
//! Neste lote a árvore é um ESPELHO: uma caixa por elemento, nenhuma anónima,
//! nenhuma gerada. `caixas_de` devolve sempre uma fatia de comprimento um. O
//! desenho inteiro está em `docs/ui/html-engine/box-tree.md`.

use crate::dom::NodeIdx;
use crate::style::ComputedStyle;
use std::rc::Rc;

/// Índice numa arena contígua, como `NodeIdx` já é para os nós. Não é
/// `Rc<RefCell<Box>>`: a árvore constrói-se numa passagem, lê-se muitas vezes
/// e deita-se fora inteira.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct BoxId(pub u32);

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum BoxKind {
    /// Um elemento que gera caixa.
    Elemento(NodeIdx),
    /// Gerada pelas regras do CSS, sem elemento nenhum por trás.
    Anonima,
}

#[derive(Debug)]
pub struct Box {
    pub kind: BoxKind,
    /// O estilo COMPUTADO, partilhado. `computed_style_idx` já devolve um `Rc`
    /// e partilha-o quando não há animação; um `ComputedStyle` tem cerca de um
    /// kilobyte, por isso várias caixas de um elemento partilham a alocação em
    /// vez de a clonarem.
    pub estilo: Rc<ComputedStyle>,
    pub pai: Option<BoxId>,
    pub filhos: Vec<BoxId>,
}

#[derive(Debug, Default)]
pub struct BoxTree {
    arena: Vec<Box>,
    /// A tradução, e o único sítio onde ela vive. `Vec` e não `SmallVec`
    /// porque neste lote todas têm comprimento um; a estrutura admite mais
    /// para que BT-3 não tenha de mexer aqui outra vez.
    por_no: crate::fasthash::FastMap<NodeIdx, Vec<BoxId>>,
}

impl BoxTree {
    pub fn push_elemento(
        &mut self,
        no: NodeIdx,
        estilo: Rc<ComputedStyle>,
        pai: Option<BoxId>,
    ) -> BoxId {
        let id = self.push(BoxKind::Elemento(no), estilo, pai);
        self.por_no.entry(no).or_default().push(id);
        id
    }

    pub fn push_anonima(&mut self, estilo: Rc<ComputedStyle>, pai: BoxId) -> BoxId {
        self.push(BoxKind::Anonima, estilo, Some(pai))
    }

    fn push(&mut self, kind: BoxKind, estilo: Rc<ComputedStyle>, pai: Option<BoxId>) -> BoxId {
        let id = BoxId(self.arena.len() as u32);
        self.arena.push(Box { kind, estilo, pai, filhos: Vec::new() });
        if let Some(p) = pai {
            self.arena[p.0 as usize].filhos.push(id);
        }
        id
    }

    pub fn caixas_de(&self, no: NodeIdx) -> &[BoxId] {
        self.por_no.get(&no).map(|v| v.as_slice()).unwrap_or(&[])
    }

    pub fn no_de(&self, id: BoxId) -> Option<NodeIdx> {
        match self.arena[id.0 as usize].kind {
            BoxKind::Elemento(n) => Some(n),
            BoxKind::Anonima => None,
        }
    }

    pub fn estilo(&self, id: BoxId) -> &Rc<ComputedStyle> {
        &self.arena[id.0 as usize].estilo
    }

    pub fn filhos(&self, id: BoxId) -> &[BoxId] {
        &self.arena[id.0 as usize].filhos
    }
}

#[cfg(test)]
mod tests;
```

//! A construção da árvore, uma passagem descendente sobre o DOM.
//!
//! Neste lote é um ESPELHO e nada mais: uma caixa por elemento, na ordem do
//! documento. Não há caixas anónimas, não há caixas geradas, e um nó de texto
//! não gera caixa — o seu estilo é o do pai inline e quem o dispõe continua a
//! ser `collect_runs`. É isso que torna o comportamento idêntico POR
//! CONSTRUÇÃO e não por sorte, que é o que a régua deste lote exige.
//!
//! As regras que vão viver aqui — blockificação, caixas anónimas, geradas —
//! estão listadas na secção 4 de `docs/ui/html-engine/box-tree.md`. Nenhuma
//! entra neste lote.

use super::{BoxId, BoxTree};
use crate::dom::{Dom, NodeIdx, NodeKind};

pub fn construir_espelho(dom: &Dom) -> BoxTree {
    let mut t = BoxTree::default();
    // A raiz do documento não é um elemento e não gera caixa; os filhos dela
    // são o ponto de entrada, tal como em `layout_document`.
    for &filho in &dom.node(dom.root).children {
        desce(dom, filho, None, &mut t);
    }
    t
}

fn desce(dom: &Dom, no: NodeIdx, pai: Option<BoxId>, t: &mut BoxTree) {
    let NodeKind::Element { .. } = &dom.node(no).kind else {
        return;
    };
    let Some(estilo) = dom.computed_style_idx(no) else {
        return;
    };
    let id = t.push_elemento(no, estilo, pai);
    for &filho in &dom.node(no).children {
        desce(dom, filho, Some(id), t);
    }
}
```

```rust
/// O rectângulo de um NÓ: a união dos das suas caixas.
///
/// É a definição da spec para `getBoundingClientRect` de um inline partido —
/// a bounding box dos border boxes dos seus fragmentos, deliberadamente mais
/// larga do que qualquer um deles. A ponte para TypeScript promete quatro
/// números por `NodeId` e continua a recebê-los.
pub fn rect_de_no(&self, t: &BoxTree, no: NodeIdx) -> Option<Rect> {
    let mut acc: Option<Rect> = None;
    for &b in t.caixas_de(no) {
        let Some(&r) = self.box_rects.get(&b) else { continue };
        acc = Some(match acc {
            None => r,
            Some(a) => a.uniao(r),
        });
    }
    acc
}
```

`Rect` has no `uniao`. Add it, taking the arithmetic from `inline_box::union_rect` (`crates/rts-dom/src/inline_box.rs:279`), and delete that function in the same change — do not leave two:

```rust
impl Rect {
    /// A envolvente de dois rectângulos.
    pub fn uniao(self, outro: Rect) -> Rect {
        let x = self.x.min(outro.x);
        let y = self.y.min(outro.y);
        let direita = (self.x + self.w).max(outro.x + outro.w);
        let fundo = (self.y + self.h).max(outro.y + outro.h);
        Rect::new(x, y, direita - x, fundo - y)
    }
}
```

**Note what disappears with it.** `union_rect` carried a sentinel: a reserved
placeholder is `0,0,0,0` and uniting it would drag the box back to the document
origin, so it had to be recognised and overwritten instead. That sentinel
existed because a single map entry could not tell "empty box at the origin" from
"no box yet". With one entry per box, a box that was never written simply has no
entry, and `rect_de_no` skips it. The ambiguity is gone by construction, not by
a special case — and that is worth saying in the commit message.

In `crates/rts-dom/src/layout/itens.rs`, change `record_node_rect` and `reserve_node_order` to take a `BoxId`. The compiler enumerates every caller; each one has a `BoxId` in scope once Task 4 threads it, so expect this task and Task 4 to land together if the tree is shared.

In `crates/rts-dom/src/dom/geometria.rs`, `bounding_component` and `bounding_components_many` call `rect_de_no` instead of reading the map directly.

## What this plan does NOT do

Named so that nobody does them here by accident:

- **No anonymous boxes.** The type admits them and Task 4's test creates one, but `construir_espelho` never produces one. That is BT-3.
- **No generated boxes.** `::before` and `::after` keep their three separate implementations. That is BT-5.
- **No change to invalidation.** `node_epoch` stays in the cache keys and still rises through DOM ancestors. Making it rise through the box tree is BT-2, and it is invariant I7 — the one whose failure is serving last frame's drawing with no ruler to catch it.
- **No change to paint order.** `at`, `hit_at`, `filhos_antes` and `merge_before` stay exactly as they are. That is invariant I5 and it dies in BT-2, replaced by a stacking traversal.
- **No text boxes.** A text node still has no box; `collect_runs` still reads the DOM and threads the inherited properties down as parameters.
- **No `getClientRects`.** The union becomes a view in Task 3, which makes the per-fragment list possible — but exposing it is a separate lot with its own bridge change.
